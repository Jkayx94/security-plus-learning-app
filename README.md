# Security+ Adaptive Learning

An Android-first, installable Progressive Web App for CompTIA Security+ SY0-701 study.

The app creates short adaptive sessions from the learner's current progress rather than presenting a fixed question order. It prioritises overdue reviews, weak concepts, low-confidence answers, repeated misconceptions, important objectives and concepts that have not yet been introduced.

## Open the app

**Live application:** https://jkayx94.github.io/security-plus-learning-app/

## First-time setup

On first launch, the app asks what it should call you.

Your chosen name is stored only in the browser on that device. It is used for personal greetings and exported backup filenames. It is not uploaded to GitHub or any remote service.

Existing users are asked to confirm a display name when the updated version first opens. Existing compatible study progress is retained.

## How adaptive sessions work

Choose only how much time you have. The session engine selects the most useful next activities using signals such as:

- overdue reviews;
- current mastery;
- incorrect or guessed answers;
- low confidence;
- repeated misconception tags;
- exam priority;
- objective weighting;
- concepts never introduced;
- recent session fatigue.

Each activity explains why it was selected.

A correct guess does not count as strong mastery. A low-confidence correct answer returns sooner than a confidently reasoned answer.

## Learning stages

Every assessable concept progresses through:

1. unseen
2. introduced
3. recognised
4. understood
5. applied
6. retained
7. exam-ready

Lesson completion only introduces concepts. Higher stages require retrieval and application evidence.

## Progress and privacy

Study progress is stored locally in the browser or installed PWA on the device being used.

Stored data includes:

- concept mastery and learning stage;
- answers, attempts and confidence;
- misconception tags;
- hints and teaching branches used;
- next-review dates;
- notes and saved memory cues;
- lesson positions;
- append-only study events;
- streak, XP and study history;
- learner display name and settings.

The app does not currently provide cloud accounts or automatic cross-device synchronisation.

## Back up progress

Open **Data, backup and migration** in the app and choose **Export**.

The downloaded JSON file contains the learner profile, event history, progress, notes and review schedule. Keep it somewhere safe, such as Google Drive or OneDrive.

To restore or move progress:

1. Open the app on the target device.
2. Open **Data, backup and migration**.
3. Choose the exported JSON file.
4. Confirm the import and migration.

Compatible curriculum IDs and existing evidence are preserved. The app does not fabricate historical progress for newly added records.

Clearing browser data, uninstalling the PWA with site data, or changing to a different website origin can remove access to local progress unless a backup has been exported.

## Install on Android

1. Open the live application in Chrome or Samsung Internet.
2. Allow the first page load to finish.
3. Open the browser menu.
4. Select **Install app** or **Add to Home screen**.
5. Confirm installation.
6. Open the installed app once while online so all offline assets can be cached.

After an update, open the website in the browser and refresh once if the installed PWA has not yet shown the new version.

## Offline behaviour

After a successful first load, the app can launch and study offline. Progress continues to be saved locally and does not require an internet connection.

A connection is required for the first installation, application updates and any future online tutor integration.

## Exam mode

Exam mode is separate from normal learning sessions. It removes teaching branches and hints, records confidence and timing, and produces post-session remediation information.

Readiness percentages are estimates, not guarantees of an exam result.

## Data sources

The application uses the approved SY0-701 curriculum and learning-unit records maintained in this project. Authoritative curriculum IDs are preserved and are not regenerated by the user interface.

## Repository and deployment

The application is deployed to GitHub Pages using GitHub Actions.

The workflow:

1. locates the application ZIP in the repository root;
2. validates and extracts it;
3. applies the current deployment patches;
4. installs the locked dependencies;
5. runs validation, tests and TypeScript compilation;
6. creates the production build;
7. verifies required PWA assets;
8. deploys `dist` to GitHub Pages.

## Current limitations

- Progress is local to one browser profile unless exported and imported.
- The current Ask AI feature is an offline curriculum-grounded helper rather than a remote generative service.
- Readiness is an evidence-based estimate and not a guarantee.
- Some full-curriculum activities are generated from authoritative mappings rather than individually handcrafted scenarios.
